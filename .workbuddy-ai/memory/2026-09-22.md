# 2026-09-22

## Android CI 链接失败：开 HXCPP_STACK_TRACE 撞上 hxcpp 的对象缓存

### 现象

CI（macOS runner 编 Android aarch64）在链接 `libApplicationMain-64.so` 时报一片
undefined symbol，两类：

```
undefined symbol: hx::ExceptionStackFrame::ExceptionStackFrame(hx::StackFrame const&)
    referenced by DefineMacro.cpp / DefinesMacro.cpp / Iris.cpp ... referenced 577 more times
undefined symbol: _hx_pos_a12cec1f7f1a6feb_18_new
    referenced by Iris.cpp: crowplexus::iris::IrisCall_obj::__alloc(...)
undefined symbol: _hx_pos_62c77a219906a331_7_new   (haxe::ui::CallLater_obj::__alloc)
undefined symbol: _hx_pos_74e540f925efc24d_3_new   (haxe::ui::filters::Blur_obj::__alloc)
... 每个都是某个类的 new
```

编译命令行里能看到宏确实生效了：
`-DHXCPP_CHECK_POINTER(haxe) -DHXCPP_STACK_TRACE(haxe) -DHXCPP_STACK_LINE(haxe)`。
但整份日志只有 `Compiling group: haxe (16 files)` —— **只重编了 16 个文件**。

### 根因：hxcpp 的对象名不含编译参数

`_hx_pos_<hash>_<line>_<name>` 的声明与定义是**分开**的：

- `include/<...>/IrisCall.h:9` → `HX_DECLARE_STACK_FRAME(_hx_pos_..._18_new)` = `extern ::hx::StackPosition ...;`
- `src/<...>/IrisCall.cpp:8` → `HX_DEFINE_STACK_FRAME(_hx_pos_..._18_new, ...)` = 真正的定义

而 `HX_DEFINE_STACK_FRAME` 在 `HXCPP_STACK_TRACE` 未定义时**展开成空**
（`include/hx/StackContext.h:81-92`）。CI 上 `Iris.cpp` 被重编（引用出现了），
`IrisCall.cpp` **没被重编**（定义还是"空"）→ 链接期符号对不上。

为什么没被重编 —— hxcpp 的两种对象命名（`tools/hxcpp/Compiler.hx`）：

| 函数 | 名字构成 | 参数相关？ |
|---|---|---|
| `getObjName(inFile)` | `Md5(targetKey + path.dir + group.mId).substr(0,8) + "_" + name` | **否**，只跟目标/路径/组有关 |
| `getHashedName(inFile, getArgs(inFile))` | `Md5(源文件内容 + 编译参数 + 依赖哈希 + 编译器版本)` | 是 |

`getCachedObjName()` 只在 `mCompilerVersion!=null && useCacheInPlace && group.isCached()`
时走 `getHashedName`，否则走 `getObjName`。CI 上的对象名是
`c2568664_DefineMacro.obj` / `57d14e5a_Iris.obj` —— **`getObjName` 形式**，
所以改 `-D` 不会让它们失效，只有 `.cpp` 内容变了的 16 个被重编。

→ **改这类全局宏必须先把 `obj/` 清掉**，否则新旧对象混链。

`hx::ExceptionStackFrame::ExceptionStackFrame` 缺失是同一件事的另一面：它定义在
`src/hx/Debug.cpp:441`（也在 `#ifdef HXCPP_STACK_TRACE` 里），属于 hxcpp 自己的库，
同样因为没重编而缺符号。

### 本次改动

`Project.xml` 的 `<section if="cpp">`：两个新宏加 **`unless="android"`**。

```xml
<haxedef name="HXCPP_STACK_LINE" unless="android" />
<haxedef name="HXCPP_STACK_TRACE" unless="android" />
```

理由：
- Android 的 `-D` 集合回到上次绿色构建的**完全相同**状态 → CI 不需要清缓存就能绿。
- Android 本来就走 `NativeCrashHandler` + 自己的 crash logger，Haxe 侧栈读不回来，
  却要付每次函数进出的 `pushFrame`/`popFrame` 代价。
- 和已有的 `HXCPP_CATCH_SEGV if="debug" unless="android"` 一个路数。

### 遗留：Windows 那棵树必须清一次对象

本地 `export/legacy-gc/windows/obj/obj/msvc1964-nc/` 有 **5389 个 .obj**，
全是没开宏时编的。下次 Windows 构建会原样复用 → **同样的 undefined symbol**。
要清的是 `export/legacy-gc/windows/obj/obj/`（不是整个 `obj/`：生成的 .cpp 内容
不随这两个宏变化，只有 C++ 预处理结果变，所以重新编 C++ 就够；但重建整个 `obj/`
更保险）。代价是一次全量重编（上次约 2 小时）。

注意：这批对象现在是一致的（都没开宏）。所以**如果决定不要栈，什么都不用做**；
一旦用新宏构建过一次，两个方向都得清一次对象。

### 待确认
