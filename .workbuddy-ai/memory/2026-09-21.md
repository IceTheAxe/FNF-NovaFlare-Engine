# 2026-09-21

## 报错处理流程改造：让 Haxe 层优先接住错误

### 诊断出的机制

NovaFlare 有两条互不相通的报错路径，同一个错误走哪条取决于一个编译宏：

- **Haxe 路径**：`Stage.__broadcastEvent` 的 try/catch → `__handleError` → `UncaughtErrorEvent`
  → `mobile.backend.CrashHandler.onUncaughtError` → 写 `crash/<时间戳>.txt`，`preventDefault()`
  让游戏继续跑。
- **原生路径**：`general.backend.NativeCrashHandler` 的 `AddVectoredExceptionHandler` +
  `SetUnhandledExceptionFilter` → 写 `native-crash-*.txt/.dmp`，`EXCEPTION_EXECUTE_HANDLER` 杀进程。

`HXCPP_CHECK_POINTER` 是分水岭：开了，`obj.field` / `arr[i]` 的空引用会走
`hx::NullReference` → `hx::Throw` → 真 Haxe 异常，被帧循环的 catch 接住；不开就是裸
`EXCEPTION_ACCESS_VIOLATION`，完全绕过 Haxe 层。

它随 `HXCPP_DEBUG` 自动开启（`.haxelib/hxcpp/git/include/hxcpp.h:109`），而 Release 没有
`HXCPP_DEBUG`，所以必须显式写进 `Project.xml` 才在 Release 生效。
转发链路：`Project.xml` haxedef → 生成的 hxml `-D` → hxcpp
`.haxelib/hxcpp/git/toolchain/common-defines.xml:12` 的 `<flag value="-DHXCPP_CHECK_POINTER" if="HXCPP_CHECK_POINTER" tag="haxe" />`。

缺口范围：`obj.field` / `obj.method()` / `arr[i]` / `arr.length` / `cpp.VirtualArray` /
`Scriptable` 受控；`null + 1`、`nullFn()` 本来就无条件抛 Haxe 异常，不受宏影响。

`Stage.__broadcastEvent` 的 `catch` 块里调 `__handleError(e)`，**不在 try 内** —— 所以
`onUncaughtError` 自己抛异常会逃出整条 Haxe 链路，变成原生崩溃（`0xe06d7363`）。

### 本次改动

- `Project.xml`：恢复无条件 `<haxedef name="HXCPP_CHECK_POINTER" />`；把
  `openfl-disable-handle-error` 笔误改成 `openfl_disable_handle_error`。
- `source/mobile/backend/CrashHandler.hx`：抽出 `writeHaxeCrashReport(kind, message, stackLabel,
  stack, callStack)`（永不抛，带同消息 2s 去重）；`onUncaughtError` 拆成外层 no-throw 壳 +
  `reportUncaughtError`，修掉 stack 遍历里 `file` 可能为 null 的 `NullReference`；
  新增 `showInGameErrorReport` 带防重入；`onError` 改为先落盘再抛。
- 新建 `source/substates/CrashReportSubState.hx`：直接继承 `FlxSubState`（不继承
  `MusicBeatSubstate`，避开 `ClientPrefs.data` / `Pathfinder` 依赖），零资源依赖，
  create/update/close 各自包 try。

### 需要记住的坑

- `FlxState.tryUpdate()` 里 `update(elapsed)` 先跑、`resetSubState()` 后跑。父 state 的
  `update()` 每帧抛异常时，`resetSubState()` 永远执行不到 → 报告界面永远建不出来。
  解法：`openSubState` **之前**先把父 state 的 `persistentUpdate = false`。
- `subState = _requestedSubState` 在 `subState.create()` **之前**赋值，所以用
  `FlxG.state.subState != null` 做防重入是可靠的。
- 项目约定的相机设置：`cameras = [FlxG.cameras.list[FlxG.cameras.list.length - 1]]`。
- `hx::CriticalError` 全 hxcpp 只在 `Debugger.cpp` 的 `HXCPP_DEBUGGER` 分支里调用，
  所以 `onError` 在 Release 下基本不会被触发 —— 降低 Release 原生报告数的是
  `HXCPP_CHECK_POINTER`，不是 `onError`。

### 验证命令（改 source/ 下 .hx 后必跑）

**先确认 haxelib 指向项目内仓库**（这是全局设置，换项目就变）：

```bash
cd /f/FNF-NovaFlare-Engine
haxelib config                          # 必须输出 F:\FNF-NovaFlare-Engine\.haxelib\
haxelib config F:/FNF-NovaFlare-Engine/.haxelib   # 不对时重新定向

haxe export/release/windows/haxe/release.hxml --no-output   # 类型检查
haxe export/release/windows/haxe/release.hxml               # hxcpp 代码生成
```

hxml 自带 `-D no-compilation`，所以第二条只做代码生成、不编译 C++。两条都 exit 0 即通过。
注意 hxml 是上次 `lime build` 生成的**快照**，不会自动反映 `Project.xml` 的新宏。
